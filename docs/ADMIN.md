# Веб-панель lerk-vpn

Панель для владельца сервиса: серверы, каскады, клиенты, конфиги Happ, маршрутизация, трафик.

## Установка одной командой

```bash
curl -fsSL https://raw.githubusercontent.com/LerkOFF/lerk-vpn/main/install.sh | sudo bash -s -- --domain vpn.example.com --email you@example.com
```

Установщик (Debian или Ubuntu, от root) ставит недостающие пакеты, создаёт пользователя `lerkvpn`, клонирует код в `/opt/lerk-vpn/app`, рабочие данные кладёт в `/opt/lerk-vpn/data`, создаёт службу `lerk-vpn`, генерирует пароль администратора (показывается один раз, копия в `/root/lerk-vpn-admin.txt`), настраивает nginx и выпускает сертификат Let's Encrypt, когда A-запись домена уже указывает на сервер. Повторный запуск безопасен: код обновится, пароль не изменится, сертификат выпустится, если раньше DNS не был готов.

Параметры: `--domain`, `--email`, `--login`, `--port` (по умолчанию 8780), `--no-nginx`, `--no-tls`, `--dir`. Без `--domain` панель слушает только `127.0.0.1:8780`.

Сменить пароль: `lerk-vpn web set-password --env-file /etc/lerk-vpn.env`, затем `systemctl restart lerk-vpn` (все входы завершатся).

## Как работать

1. **Серверы и каскады**: «Добавить сервер» (IP, логин, пароль, роль). Панель войдёт по паролю один раз, положит свой SSH-ключ, поставит Xray, swap и BBR. Пароль не сохраняется.
2. Роль «Сервер 1» это вход для клиентов, «Сервер 2» выход в интернет. В блоке «Создать каскады» отметьте несколько серверов 1 и один сервер 2: на каждый сервер 1 создаётся каскад до сервера 2.
3. «Собрать цепочку из нескольких серверов»: выберите вход, добавьте сколько нужно промежуточных серверов (кнопки ↑ ↓ меняют порядок) и выход. Путь клиент → вход → звено → … → выход → интернет показывается над кнопкой. Любой сервер можно поставить на любое место, один сервер может входить в разные каскады, в одном только один раз.
4. «Прямой доступ (без каскада)»: отметьте серверы, на которых клиент должен выходить в интернет сразу, без второго сервера.
5. «Порты и параметры серверов»: порт Xray, порт SSH, SNI, fingerprint, flow, мультиплексирование mux и число потоков, swap, блокировка торрентов, файрвол ufw. После изменений нажмите «Применить».
6. Переименование и удаление: в каждом сервере и каскаде есть формы имени, названия (его видит клиент в Happ) и страны; сервер можно удалить вместе с его каскадами. Сам сервер и Xray на нём при удалении не трогаются.
7. **Клиенты**: создание, отключение, смена ключа, заметка, привязка к каскадам. В карточке клиента ссылка подписки, deeplink для Happ и QR-код.
8. **Маршрутизация**: российский трафик идёт напрямую, остальное через VPN (см. ниже).
9. **Настройки**: название профиля, интервал обновления подписки, объявление, сбор статистики, безопасность. Блок «Обновления» с кнопками «Проверить обновления», «Установить обновления», «Откатить».

## Маршрутизация (российский трафик напрямую)

По умолчанию включено и активно:

- домены `.ru`, `.su`, `.рф` (`domain:ru`, `domain:su`, `domain:xn--p1ai`);
- всё, что находится в России: `geoip:ru` и `geosite:category-ru`;
- российские сервисы: Яндекс, VK, Mail.ru, Сбер, Т-Банк, Ozon, Wildberries, госуслуги, банки, магазины, СМИ;
- частные сети (`geoip:private`).

Остальное идёт через каскад. Можно добавить свои правила «напрямую», «через VPN» и «блокировать» отдельно для сайтов и адресов, искать теги в каталоге geo-баз и проверить, что произойдёт с конкретным доменом или IP. Geo-базы (Loyalsoldier v2ray-rules-dat) скачиваются при первом запуске и обновляются раз в неделю или по кнопке. Профиль доходит до клиента заголовком `routing` в подписке, Happ применяет его при обновлении подписки.

## Адреса

| Адрес | Назначение |
|---|---|
| `/` | панель (вход по логину и паролю) |
| `/sub/<токен>` | подписка клиента: base64 со ссылками, заголовки Happ; `?format=plain` без base64 |
| `/health` | проверка службы |

## Как считаются числа

Трафик клиента берётся из API статистики Xray на сервере 1 (счётчики `user>>>c.<каскад>.<клиент>`), панель опрашивает серверы раз в заданный интервал и копит приращения в SQLite. Периоды считаются по Москве, сравнение идёт с предыдущим таким же периодом. Если данных нет, показывается «нет данных», а не ноль.

## Безопасность

Хеш пароля scrypt, лимит попыток входа, подписанная cookie (смена пароля завершает все сессии), CSRF-токен на каждом действии, CSP без встроенных скриптов, `noindex`, `no-store`, `X-Frame-Options: DENY`. Журнал действий хранит, кто и что менял. Ссылки подписки содержат длинный случайный токен; смена ключа клиента выпускает новый токен.
