# lerk-vpn в консоли

Это описание работы из командной строки. Про веб-панель смотрите [README](../README.md) и [ADMIN.md](ADMIN.md).

Автоматическая установка и настройка каскадных VPN на Xray (VLESS + Reality).
Вы описываете серверы и цепочки в одном файле, инструмент сам готовит серверы, выпускает ключи и ссылки для клиентов и проверяет, что трафик действительно идёт по цепочке.

```
клиент  ->  сервер 1 (вход)  ->  сервер 2  ->  ...  ->  последний сервер (выход)  ->  интернет
```

Что делает `apply` на каждом сервере: проверяет систему (Debian и Ubuntu), ставит swap нужного размера, включает BBR, устанавливает Xray (последний или закреплённой версии), при желании включает ufw, кладёт конфиг с резервной копией, проверяет его `xray run -test` и перезапускает службу только если конфиг изменился. Повторный запуск безопасен.

Ничего устанавливать на сервер заранее не нужно. На компьютере оператора нужны только Python 3.11+ и `ssh`. Сторонних зависимостей нет.

## Установка

```bash
git clone https://github.com/LerkOFF/lerk-vpn.git
cd lerk-vpn
python3 -m venv .venv && . .venv/bin/activate
pip install -e .
lerk-vpn --version
```

## Быстрый старт

```bash
lerk-vpn -C ~/vpn/shop init        # рабочая папка с примером topology.toml
$EDITOR ~/vpn/shop/topology.toml   # адреса серверов и цепочки
export LERK_VPN_DIR=~/vpn/shop     # чтобы не писать -C

lerk-vpn plan                      # проверить описание, увидеть роли серверов
lerk-vpn bootstrap                 # если на серверах ещё нет вашего SSH-ключа (вход по паролю)
lerk-vpn client add ann --chain main --note "Анна"
lerk-vpn apply                     # установить, настроить, проверить цепочки
lerk-vpn links ann                 # ссылки vless:// для приложения (Happ, v2rayN, Hiddify и др.)
```

После `apply` каждая цепочка проверяется сквозным запросом: на последнем сервере поднимается временный клиент, ходит через вход цепочки и сверяет внешний IP с адресом выходного сервера.

## Описание топологии

`topology.toml` в рабочей папке. Полный пример: [`examples/topology.example.toml`](../examples/topology.example.toml), несколько цепочек на общих серверах: [`examples/topology.multi.example.toml`](../examples/topology.multi.example.toml).

| Параметр сервера | По умолчанию | Смысл |
| --- | --- | --- |
| `host` | обязателен | IP или домен сервера, по нему подключаются соседние звенья цепочки |
| `public_host` | `host` | что писать в ссылках клиентов (например домен входного сервера) |
| `ssh` | нет | алиас из `~/.ssh/config`; тогда `host`, `ssh_user`, `ssh_port` для входа не используются |
| `ssh_user`, `ssh_port` | `root`, `22` | параметры SSH |
| `port` | `443` | порт входа Xray |
| `sni` | `dl.google.com` | сайт для маскировки Reality, должен отдавать TLS 1.3 |
| `fingerprint` | `chrome` | отпечаток TLS-клиента |
| `swap_gb` | `4` | размер swap, `0` не трогать |
| `bbr` | `true` | включить BBR |
| `firewall` | `false` | поставить ufw и открыть только SSH и порт Xray |
| `block_torrents` | `true` | резать торренты на выходных серверах |
| `password_env` | нет | переменная окружения с паролем root для `bootstrap` |
| `country` | пусто | двухбуквенный код, для отчётов |

Значения общих настроек задаются в `[defaults]`. `xray_version = "26.11.9"` на верхнем уровне закрепляет версию Xray.

Цепочка: `path` перечисляет серверы от входа к выходу. Один сервер (`["fi1"]`) даёт обычный VPN, три и больше дают тройной каскад. Один сервер может быть входом одной цепочки, звеном второй и выходом третьей.

## Клиенты

Клиенты лежат в `clients.json`, управляются командой:

```bash
lerk-vpn client add ann --chain main --chain double   # несколько цепочек сразу
lerk-vpn client list
lerk-vpn client disable ann        # отключить (ссылки перестают работать после apply)
lerk-vpn client enable ann
lerk-vpn client rotate ann         # выпустить новые UUID и токен подписки
lerk-vpn client rm ann
lerk-vpn apply                     # довезти изменения до серверов
```

Для каждой пары клиент и цепочка выпускается отдельный UUID, поэтому отключение одной цепочки не трогает остальные.

## Подписки

```bash
lerk-vpn export                    # out/subscriptions/<клиент>.txt и .b64
lerk-vpn serve --port 8088         # GET /sub/<токен> отдаёт подписку (base64), ?format=plain даёт список ссылок
```

`serve` слушает `127.0.0.1`; наружу его публикуют через nginx с HTTPS. Токен у каждого клиента свой, отключённый клиент получает 404, запросы в журнал не пишутся.

## Команды

| Команда | Что делает |
| --- | --- |
| `init [папка]` | создаёт `topology.toml`, `clients.json`, `.gitignore` |
| `plan [--show-config СЕРВЕР]` | проверяет описание и показывает роли; с флагом печатает итоговый конфиг Xray |
| `bootstrap [сервер...]` | кладёт ваш публичный ключ на серверы, входя по паролю |
| `apply [сервер...] [--dry-run] [--no-verify]` | устанавливает и настраивает, обновляет ссылки, проверяет цепочки |
| `chain add сервер1 сервер2 ... серверN [--name имя] [--title название]` | собрать цепочку из любого числа серверов, последний выходной |
| `chain list` / `chain rm имя` | список цепочек / удалить цепочку |
| `verify [--chain имя]` | сквозная проверка цепочек |
| `status` | состояние Xray, swap, ресурсы и совпадение конфига с описанием |
| `client ...` | управление клиентами |
| `links [клиент] [--plain]` | ссылки vless:// |
| `export` | файлы ссылок и подписок в `out/` |
| `serve` | HTTP-сервер подписок |

## Как это устроено

На каждом сервере один вход VLESS + Reality: один порт, одна пара ключей. В нём два вида пользователей: клиенты (если сервер первый в цепочке) и звенья (если сервер идёт после первого). Маршрут выбирается по email пользователя, поэтому через один сервер одновременно проходит любое число цепочек. Конфиг строится детерминированно из `topology.toml`, `clients.json` и `state.json`, так что `apply` каждый раз приводит сервер к описанному состоянию.

- Серверы применяются от выхода ко входу: когда запускается вход, следующее звено уже слушает.
- Предыдущие конфиги Xray сохраняются на сервере в `/usr/local/etc/xray/backup` (последние 10).
- Ключи Reality выпускаются на машине оператора (X25519 на чистом Python), Xray для этого не нужен.
- Если связка не проходит проверку `xray run -test`, сервер не перезапускается и остальные серверы не трогаются.

## Безопасность

- `state.json` (ключи Reality, UUID клиентов, токены) создаётся с правами 600. `clients.json`, `state.json` и `out/` уже в `.gitignore` рабочей папки; не публикуйте их.
- Пароли root инструменту не нужны, кроме `bootstrap`. Он берёт пароль из переменной окружения (`password_env`) или спрашивает в терминале и не сохраняет его.
- Конфиг на сервере доступен только root и группе службы Xray.
- Выбирайте для `sni` сайты, которые стабильно отдают TLS 1.3 и расположены рядом с сервером. Популярные цели вроде `www.microsoft.com` Xray помечает как повышающие риск блокировки.

## Разработка

```bash
python3 -m unittest discover -s tests -t .
```

Тесты не ходят по сети: проверяются криптография ключей (векторы RFC 7748), сборка конфигов и ссылок, валидация описания и команды CLI.
